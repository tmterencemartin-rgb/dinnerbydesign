# React Key Strategy Documentation

This document serves as the canonical record for React key strategies used across dynamic lists in `App.tsx` to prevent duplicate-key warnings and ensure component stability.

## Guiding Principles & Hierarchy

1.  **Primary (Persisted IDs):** Use stable, unique IDs from the database (Firestore) whenever available. This is the gold standard for component identity.
2.  **Secondary (Deterministic Composite Keys):** When no database ID exists, derive a unique key from the underlying data properties (e.g., `type-value-label`). Use this for stable but calculated lists.
3.  **Fallback (Ephemeral Suffixes):** Index-based suffixes (`-idx`) are used **only** as a fallback for transient, UI-only lists where data may not be perfectly unique across identical values. This is discouraged for data-driven lists.

## 1. Core Data Lists (Database IDs)
These lists rely on unique, persistent IDs generated by Firestore or passed from the server.
- **Saved Recipes / Planner**: `recipe.id` (Firestore UID)
- **Shopping List Items**: `item.id` (Firestore UID)
- **Profile Selections (Allergies/Ethical)**: `${prefix}-${item}` (e.g., `allergy-Peanuts`). Items are unique strings deduplicated at the state level.

## 2. AI-Generated Results (Deterministic Search Batch Identity)
Generated in `performSearch` to guarantee identity stability for a single generation cycle.
- **Recipes**: `ai-recipe-${titleSlug}-${currentSearchId}-${ArrayIndex}`
- **Ready Meals**: `ai-meal-${titleSlug}-${currentSearchId}-${ArrayIndex}`
- *Note*: `currentSearchId` is a ref-based counter that increments once per search event. This ensures that items in a single response (including those recovered via partial JSON repair) share a stable identity, but a fresh search triggers fresh component identity for animations.

## 3. Ephemeral & Diagnostic Lists
- **Diagnostic Panel Logs**: `log-${log.id}-${idx}`. `log.id` includes a session counter and random suffix.
- **Active search criteria (Deduplicated)**: `criterion-${type}-${value}-${label}`. 
  *   *Logic*: Items are filtered through a `seenCriteria` Set before rendering to ensure deterministic uniqueness even if overlapping preference sources exist.

## 4. Derived & UI-only Lists (Fallback Pattern)
Index suffixes are utilized here for transient UI states where perfect uniqueness is not guaranteed by the label alone.
- **Alternative Suggestions**: `alt-${titleSlug}-${idx}`
- **Temporary Filter Pills (Exclusions/Methods/Fats)**: `search-${type}-${value}-${idx}`
- **Planner Day Picker**: `day.id` (Standard ISO date string)
- **Dropdown Options**: `opt` (Derived from static taxonomy keys)
